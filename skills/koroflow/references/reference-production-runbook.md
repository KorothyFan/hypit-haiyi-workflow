# 参考复刻：从选题到交付的执行流程

更新：2026-11-04。适用于已选参考片、角色替换、换场景／元素、多版本及状态变化的制作；与[完整制作规范](production-standard.md)一起使用。它是按实际依赖推进的制片方法，不是新增的自动执行器，也不要求简单任务填完所有表格。

仅学习方法或交给新AI／同事时，可用[轻量交接与启动词](../assets/templates/reference-task-handoff.md)，不必恢复全部历史作品或引入入库系统。真实续作才恢复相应工程、原任务与版本。用户负责方向与审美反馈，执行者负责可从现有资料完成的理解、准备和核对；只有确实缺失且影响执行的信息才询问。

2026-11-10迁移补充：新机器先按仓库 `docs/laptop-setup.md` 选择实际执行器、重新配置和授权；已安装技能可用 `scripts/migration.py` 与技能内空模板离线检查。新片不要求搬旧库存，真实续作才带相应版本和原任务。纯图片输入见[多图参考重建](production-paths/image-reference-rebuild.md)。

## 1. 恢复要求，先核对是否已经做过

读取本次委托、现行角色与声音偏好、已有工程和真实任务。分别确认“只分析”“制作”“修订”“打包”范围，不因项目已有账号就开始生成。

- 有历史库存或外部来稿时，先按来源ID、文件指纹、剧情动作与镜头关系对照。相同指纹证明同文件；不同文件也可能是同一模板的复刻，不能只按文件名去重。
- 留下逐条结论：已有可用版本／需修订／拟新做／尚未确认，以及对应文件和依据。“没在本批找到”不写成“所有历史都没有”。用户明确要新做一个版本时按委托执行。
- 旧作品修订沿用work_id；角色组合和版本安排以当次要求为准，不自动拓展角色或配额。

本阶段输出：本次实际要做的独立作品列表、已有结果入口及重复项处理决定。

没有旧库时只报告“本次可访问范围未命中”，不把新机器当历史从未做过。先记录当前用户的保留／暂停／不重做决定，草稿修订不能覆盖后续决定。

## 2. 看懂完整原片，保存可追溯参考

保存来源、原件、编码／尺寸／帧率／视频轨时长与指纹。完整理解剧情、动作因果、角色职责、道具接触、表情变化、机位和结尾；可用覆盖全片的采样辅助定位，未完整动态查看或未听音时分别标记。

开场明确角色和关键道具已在哪里、被什么遮挡；区分开柜／视角变化后露出与当下凭空出现。输入兼查标称和平均帧率、视频轨与容器时长，规范化另存并说明时间映射；下限按当前模型查询，不固定所有参考30fps。末段重点回放，必要时加密采样，不用稀疏抽帧否定实际掉落或结尾动作。

原件不覆盖。平台需要兼容编码或不采用源音轨时，另做参考副本，记录转码、去声、裁切或分段的用途；核对尺寸、帧率、帧数、时长及时间映射。保留全部帧的转码不叫原文件不变，也不证明像素无损。去声不是所有任务的默认，声音复用看[D路径](production-paths/visual-only-audio-preserve.md)。

确需裁切画幅时跟随主角与剧情需要的活动区域，容纳关键动作、道具和结尾，不能机械居中；若无法同时保留关键内容，先调整构图方案，不将裁掉的内容当原片不存在。

时长限制查当前平台与具体模式：完整原片符合输入及输出要求时可整段参考；只有实际限制或叙事需要才分段，不把某次模型上限或旧素材切点当通用规则。

## 3. 做版本映射，分开身份、职责、状态与声音

采用[批次制作交接表](../assets/templates/reference-production-batch.md)，小任务可仅保留相关行。

| 要固定什么 | 记录方法 |
| --- | --- |
| 源剧情职责 | 源角色A先做什么、B如何反应、谁经历变化、结尾由谁完成；角色移动后仍沿用稳定ID |
| 本版身份 | 源角色ID → 目标角色 → 核准身份资产；互换剧情位置时不交换声音身份 |
| 状态触发 | 初始状态 → 具体动作 → 新状态；归属、左右侧、服装与道具持续到哪里 |
| 场景与元素 | 哪些可换，哪些布局、接触、活动空间和结构条件必须保留 |
| 声音 | 各目标角色的完整用词／读法、音色、情绪、停顿、空间及真实发声部位；音色参考与最终音轨分开 |

换款不能破坏动作：可穿戴、可抓取、能闭合／承重等剧情所需结构要保留。状态图只在对应事件后生效，不能让变装提前出现；一人的新服装不套到同伴身上。身份图的静态表情不固定后续表演。

若本地启用换景／换元素偏好，列“原元素→新元素→保留的结构、接触和笑点机制”，结果检查真实落实，不以局部改色代替换景。材质变化连同工具、物理、残留和食用／制作动作一起处理；原片持续带错时可提出图参考重建，但不能自行付费改道。

## 4. 按缺口准备资产，先检查再绑定

能直接用身份图与原片完成的，不为形式新增付费图。需要换空间、道具或特殊状态时，按风险补图，参考[A+C状态方法](production-paths/state-and-prop-continuity.md)。不固定每版两张或四张；已核准资产可以跨版复用，绑定数和独立生成数分开。

逐张检查身份、比例、材质、发色、肢体、持握、服装、道具归属及变化前后。空景混入错误人物时，可在不破坏动作空间与透视的前提下裁取建筑区域，另存派生图，记录父文件指纹、处理和用途；局部清理也保留原图并重查结构。裁切不够用时留待处理，不硬把错误图传下去。

提交前更新[素材与状态绑定表](../assets/templates/state-asset-binding.md)：正式提示词的“图片1／视频1”等标签必须与实际请求数组、文件版本和SHA256逐一对应。表里写过附件，不代表它已经实际上传。

## 5. 写本版正式提示词，核对真实请求

原片参考时，直接写“严格参考原片的剧情、动作、表情变化和镜头关系，自然安排动作衔接”，再说明本版角色映射、允许替换项、状态触发、结尾、声音与画内文字要求。只为容易错的因果或接触补必要细节，不用“让模型……”的转述，不另造一套逐秒动作与原片竞争。

参考[提示词骨架](../../hypit-haiyi/references/prompt-direction.md#原视频参考的正文骨架)时删掉不存在的附件与无关条件，按实际平台语法转换；同步、真实输入限制或明确导演要求确有需要时再用精确时间，不把计划时间声称为执行保证。

每个请求只包含本版的身份、服装与声音，跨版本分析留在制作清单。核对模型ID、模式、精确价档、时长、分辨率、音频、输入限制、特殊开关和扣费来源；展示可打开的正式提示词、实际附件与费用未知项。

本地要求海艺原生音频时，Seedance正式请求显式 `generateAudio: true`，声音提示词同时包含动作、环境与角色反应。无BGM、参考去声、背景修订或准备复用旧音轨不改变此策略；当次明确静音例外单独记录。纯图请求不引用／携带视频，参考图与字面边界帧分开。

用户明确制作指令与既有约定已覆盖的请求，在预检后继续，不逐图逐镜重复确认；“先看方案／暂停”优先。没有明确授权的付费重试、升档、追加步骤或切换扣费来源不自动执行。预算未指定与价格未知分别写明，不能自行填成无限预算或零费用。

## 6. 按依赖提交，沿原任务接收结果

检查通过的资产才能进入对应视频请求。独立版本可在实际限流与授权内并行；有续段依赖时先核对前段，再用实际尾帧和当前状态。每个请求保留最终参数、指纹、提交时间、远程任务号和回执。

每个work_id／revision／任务号单独存请求、回执、原生文件和采样证据，避免覆盖固定的“首次回执”或“全片采样”文件。审片页从所选revision真实记录生成状态，不写死“待审”；用户已接受与操作者not_checked可以同时存在。

等待超时只继续查询原任务。成功项保存原生文件；失败、运行、结果未知和暂停分别留档。审片页可随结果更新，但不能将“能打开进度页”称为成片已交付。

失败保存原始错误与实际参数，不凭泛化审核提示断言触发原因，不把修改参数当免费重试。用户要求完成后提醒时只跟进现有任务，正常等待安静，完成或遇到需处理的阻塞再说明；跨回合持续跟进须使用实际可用的任务／自动化能力，不能仅靠文字承诺监控。

## 7. 检查真实文件，按问题选择最小修订

先做完整解码、实际画幅／时长／编码／音轨检查，再实际看全片、听声音，分别记录已查与未查。多版本重点检查职责是否串位、造型是否在正确事件后变化、原片帽子等是否残留、背景同款是否错人、立体材质是否在所有角色及镜头保留、结尾是否完整。

比例检查覆盖近身接触、伸手、抬腿、跳起与遮挡后恢复，不只检查身份首帧。实际输出时长与结尾也要复核，不能凭“自动沿输入时长”的参数说明判通过。

- 画面采样可报告可见偏差，不能替代连续动作与声音听审。清楚区分“说词完整”“音色可爱”“情绪适当”“口型对应”，不能只凭有音轨就判通过。
- 用户只要修订一个问题时保留其他已接受要求；付费重做按本次有限范围执行，不能把其他版本一并重做。
- 用户明确要求本地补音时，可从允许复用的原生音轨选完整发声回合。对照实际首次张嘴与起音确定进入点，核对结束、停顿和环境声；不靠单帧或固定秒数认定同步。原生版、混音版及旧候选分别保留，记录取样区间、目标区间、混音参数与文件指纹。
- 仅混音时按实际处理核对画面是否变化；“尺寸与帧数一致”不能单独证明视频流或画面逐帧相同。技术核对与主观听感仍分别记录。

先判断问题出在资产、映射、提示词、参数、生成结果还是后期，再选择最小修订；下表是诊断顺序，不是自动付费重做指令。

| 具体问题 | 优先定位与处理 |
| --- | --- |
| 身份或比例不稳 | 查实际上传的身份图、参考职责与正文冲突，不先增加无关细节 |
| 缺件或服装持续漂移 | 查状态资产、归属、触发事件与持续范围，按缺口补图 |
| 剧情职责串位 | 固定源角色ID，明确动作对象、帮助者、佩戴者和变化者；互换不是全片镜像 |
| 动作偏离参考 | 删除额外剧情和竞争性逐秒描述，保留真实参考及必要因果约束 |
| 场景资产有错人 | 判断可逆裁切／局部处理是否保留结构，未解决就不下传 |
| 画面已接受但叫声缺失 | 按用户选择作原生修订或已授权补音，不自行贴声覆盖 |
| 补音晚于张嘴 | 对照实际首次张嘴与完整回合，调整进入点、结束点和自然停顿 |
| 后段或结尾未提供 | 先查输出和审片页链接，再检查段长、接点与完整合并版，避免误重生成 |

## 8. 交付、采用、统计与成本复盘

准备可播放审片页、正式文件、英文发布标题和已知问题。用户要桌面打包时复制所选版本并逐一校验，不覆盖工程原片；文件命名明确平台原生、分段拼接或本地声音修订。

候选可供查看、用户要求文件交付、质量验收和确认采用是不同事实。用户要求打包已知有瑕疵的候选时照实记录“文件已提供／用户要求交付”及未通过项；不得伪造核心必检通过来调用deliver。核心质量门槛和现有项目台账分别遵循其真实记录方式。用户说“都采用”时关联可确定的work_id与版本；存在多版歧义则保留待确认，不扩展到后续修订，也不推定平台发布。

成功视频任务按任务号去重，独立交付按work_id去重；图片、本地剪辑、复制和再次导出不增加视频生成数。新增事实只追加本作品事件，通过现有刷新器更新，保留人工发布字段。

成本复盘分开实时标价估算、平台回执cost及已核实账单：保留单位，未注明币种的cost不直接当人民币。按任务号去重并注明日期、模型档位、成功／失败／未知范围；“生成每秒消耗”用纳入任务消耗总和除以对应实际生成时长，“每作品累计消耗”另计绑定资产、各次重做及缺失项。历史均价不冒充新请求的实时报价，且不包含未纳入的人工或其他工具费用。

本流程依据实际制作反复整理；模型、角色名、精确图数、服装材质、分段秒数和价格留在各项目。公开指南只放可迁移方法，私人清单、完整客户提示词和媒体不随仓库分发。
